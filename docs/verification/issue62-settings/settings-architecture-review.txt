## Findings

### M1: Known preset alias can disable the configured SHA check

- Severity/status: Medium, open; AC005/006, IC003 and AF062-S2.
- Evidence: `agentic_rag/neural_rerank.py:124` and `:151`,
  `agentic_rag/reranker_profiles.py:22-24`.
- Reproduction: construct `replace(Config(), rerank_revision='0'*64)` and mock
  discovery with the actual mMARCO alias and its catalogue SHA. Return valid
  complete scores from POST. Call `order` with eligible synthetic hits. Observed
  request methods are `['GET', 'POST']`; the configured SHA does not match the
  advertised SHA. A TOML manual model/revision declaration reaches the same path.
- Cause/impact: `identify` requires both alias and catalogue SHA. A mismatched
  configured SHA makes a known managed model look custom, so `revision=None`
  removes identity validation before passage transfer. Source text reaches a
  runtime that does not match the configured identity.
- Fix direction: determine managed identity from the alias independently of SHA
  equality, and require exact configured SHA discovery for every managed alias.
  Keep the deliberate alias-only contract for genuinely custom/legacy aliases.
  Add the wrong-configured-SHA case as well as the existing wrong-runtime-SHA case.

### M2: Cancellation before worker start permanently occupies the native slot

- Severity/status: Medium, open; AC005/006, runtime pressure/recovery boundary.
- Evidence: `agentic_rag/reranker_runtime.py:140-151`.
- Reproduction: use `create_app` with a synthetic ranker and an event-loop default
  executor with one worker. Occupy that worker with an Event, start an ASGI rerank
  request, cancel its task while inference remains queued, then release the
  blocker. The next valid request returns 429 although no inference ever ran.
  The standalone synthetic probe exited 0 and printed
  `AFTER_CANCEL_WITH_NO_NATIVE_INFERENCE_STATUS 429`.
- Cause/impact: the event-loop task acquires `gate`, but only `execute` releases
  it. Cancelling the queued executor future prevents `execute` from running.
  Subsequent calls remain on deterministic fallback until daemon restart.
- Fix direction: make worker ownership cancellation-safe. A protected submitted
  worker must eventually release the slot, or cancellation before native start
  must release it exactly once. Do not release an active native slot merely
  because its HTTP waiter was cancelled. Cover both before-start and active-work
  cancellation with an accepted subsequent request after drain.
