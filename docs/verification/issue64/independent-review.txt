### L-1 Parser treats version numbers and common words as date expressions

- Requirement: AC-001/FR-001 (recognize supported intent), AC-006 (no-intent parity).
- Where: `agentic_rag/temporal.py:45-49,53`.
- Evidence (`/dev/shm/rag64-20261031-tests/review/version-probe.log`,
  `aktuell-probe.log`, probe OBS X3/X3b), reference 2026-10-31, Europe/Berlin:
  - `rag upgrade 0.6.16 failed gestern` → `ambiguous` (`0.6.16` matched the two-digit-year
    pattern although day 0 is no date); same for `rollout 1.12.25 last week`,
    `Python 3.13. upgrade yesterday`, `Raum 3/12 Drucker gestern`.
  - `release 0.6.17 notes` → `unsupported`.
  - English modal `may 3`, the name `August 2`, and the German adjective
    `aktuelle/aktuellen` (`aktuelle Rechnung vom 14.10.2026` → `ambiguous`,
    `conflicting_expressions`).
- Effect: with a real period present, `prefer` is not applied (warning) and `filter`
  is rejected with `temporal_filter_requires_interval`. With `enabled = true` and no
  period, `auto` adds a warning and a `temporal` envelope; hits stay identical.
- Suggested fix: validate day/month ranges before classifying numeric forms as
  unsupported dates; require a date context (`on`, `am`, year) for EN `may` and month
  names; match only `aktuell` / `currently` as the current-intent adverb.

### L-2 Long no-intent queries change the envelope under enabled `auto`

- Requirement: AC-006 ("no temporal intent preserve baseline … fields").
- Where: `temporal.py:197-198`, `search.py:70-71`.
- Evidence: probe OBS X2, 1,110-character query without a period, enabled `auto`:
  extra warning `temporal expression not applied: unsupported`, status `unsupported`,
  reason `query_too_long`; hits identical to off.

### L-3 Several temporal phrasings are neither applied nor reported

- Requirement: AC-001 ("unsupported forms are reported conservatively"); docs list of
  reported forms.
- Where: `temporal.py:50-62`.
- Evidence: probe OBS X5: `vergangene Woche`, `previous week`, `past week`,
  `kommenden Monat`, `im Oktober 2026` → status `none`, no reason. Not guessed and
  `filter` fails closed correctly, but `prefer`/`auto` silently treat them as no intent.

### L-4 Out-of-range reference surfaces as an internal failure

- Requirement: IC-001 failure behavior ("bounded ValueError/400").
- Where: `temporal.py:94` and `:207` (`astimezone` outside the guarded block).
- Evidence: probe OBS X1: references `9999-12-31T23:30:00+00:00` and
  `0001-01-01T00:30:00+01:00` raise `OverflowError`; REST answers 400
  `operation_failed`, not `invalid_arguments`. The local CLI maps non-`ValueError` to
  exit 4 "unexpected error" (`cli.py:1084-1089`; code-read, not executed because the CLI
  would open the configured database).

### L-5 Empty `temporal` string is coerced to `auto`

- Where: `mcp_server.py` `temporal=temporal or "auto"`; library `validate_mode('')`
  rejects it.
- Evidence: probe OBS X4: REST `{"temporal": ""}` → 200 legacy envelope.
