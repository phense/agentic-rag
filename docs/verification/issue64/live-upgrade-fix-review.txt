## Findings

### M1 — L10 fresh package is not root-only; postgres gains read access to root-only recovery config

- Where: `docs/playbooks/system/rag-064-live-temporal-upgrade.md:89-103` (L10 snippet), text at `:86`
  ("make a distinct root-owned package").
- Mechanism: the snippet calls `ops.produce(package)` directly instead of going through `main()`/`publish()`.
  `produce()` does `os.chown(stage, postgres)` (helper line ~133) and the snippet never chowns back; `publish()`'s
  post-steps (`chown 0:0`, `chmod 0600` per file, stage `0700` root) are skipped. The snippet also does not set the
  helper's `os.umask(0o077)` (`main()`), and the service's `UMask=0077` does not apply to `sudo python3 -`.
- Evidence (live, read-only): `sudo sh -c umask` → `0022`; `nwb-rag-backup.service` has `UMask=0077`;
  `/var/backups/agentic-rag` is `root:postgres 0710`; existing daily packages are `root:root 0700`;
  `/etc/agentic-rag` is `rag:rag 0700` and `sudo -u postgres test -r /etc/agentic-rag/server.toml` → cannot read.
  Result of the snippet as written: package dir `postgres:postgres 0700` (traversable via the 0710 parent), root-created
  `recovery.tar.gz` and `roles.sql` mode `0644` → the postgres OS account can read an archive of `/etc/agentic-rag`,
  `/usr/local/lib/nwb-rag-ops`, systemd units and launcher sources, and can also rename/replace members inside its own
  directory. The package is retained indefinitely (non-date name, outside `managed_days` rotation).
- Impact: widens a privilege boundary the daily helper deliberately keeps (DBA account → service configuration/auth
  material), on a persistent artifact; contradicts the playbook's "root-owned" statement. No data loss; backup content
  itself is correct.
- Minimal fix (playbook only): in the snippet, `import os; os.umask(0o077)` before `package.mkdir(mode=0o700)`, and after
  `ops.produce(package)` mirror `publish()`: `for p in package.iterdir(): os.chown(p,0,0); p.chmod(0o600)`, then
  `os.chown(package,0,0); package.chmod(0o700)`; only then `ops.validate_package(package)`. Optionally hold
  `/var/lib/nwb-rag-ops/backup.lock` (`fcntl.flock` EX|NB) around produce so it cannot overlap a timer run — the table
  restarts the timer first (next run 03:00 Berlin, so overlap is unlikely, see L-2).
  Add an expected-observation check: `stat` shows `root:root 0700` dir and `0600` members.
