## Finding

**RAG062-V2-001 — Medium: duplicate temporal requests inflate quality observations.**
`scripts/build_reranker_corpus.py:48-54` creates EN and DE cases with the identical
`subject + ' status'` request, same domain/project/as_of and expected sources.
`rerank_evaluation._phase` counts both IDs as independent quality observations.
Thus the three new held-out families have 24 IDs but only 21 distinct request
contracts. The same duplicate occurs in dev-orbit. This violates the sealed
one-observation-per-unique-query contract and labels language-neutral text twice.
Use genuinely distinct EN/DE temporal queries supported by the bilingual source
text, or deduplicate identical request contracts and report actual language-neutral
coverage. Add a request-contract uniqueness regression before model evaluation.
Sent to coordinator and independently rechecked after correction: the generator
now retains only one short temporal request per family. The active held-out
corpus has 21 distinct requests, and validation rejects duplicated request
contracts regardless of row ID or language/label metadata. Its regression copies
a real case under another ID and requires rejection. **Verified resolved.**

No Critical or High finding identified. No other Medium bug identified in this
bounded experiment/rollback diff.
