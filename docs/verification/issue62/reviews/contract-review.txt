## Findings

1. **Medium — reference service-class evidence is silently narrowed.**
   `docs/openspec/changes/measured-reranker/design.md:44-46` replaces Issue62's
   reference-class memory/CPU measurements with an explicitly different shared
   8CPU/16GiB host; proposal AC062-006 and task C062-004 omit the original gate.
   Disclosure makes host results honest but does not satisfy the missing gate.
   Minimum resolution: put the gate back. Run the complete measured service
   workload (owned PostgreSQL, inference runtime and evaluator, including children)
   together under an effective four-CPU/eight-GiB boundary, with zero swap, and
   record cgroup paths, effective cpuset/quota/memory limits, member PIDs, peak
   memory, CPU usage/throttling and OOM events. If cgroups cannot be delegated,
   use a real reference-class VM or preserve this as an explicit acceptance blocker.
   Thread counts or CPU affinity alone do not bound the service's memory/CPU.
   Label constrained shared-host results accurately; retained filesystem caches
   and host contention still prevent dedicated-machine/cold-disk capacity claims.

2. **Medium — failure-class reconstructions lack a confirmed-failure gate.**
   `docs/openspec/changes/measured-reranker/design.md:29-32` permits invented
   class-based fixtures without requiring an observed baseline failure. Issue62
   requests evaluation derived from confirmed failures. A plausible synthetic
   pattern is not evidence that the baseline actually fails on that case.
   Minimum resolution: reuse public Issue35 cases where suitable; add per-case
   attribution to the exact prior failure/result and an independently reproduced
   baseline miss under the supported source revision. Keep representative controls
   separately labelled. Preserve all attempted reproductions and rejected cases;
   choose development/family separation before inspecting held-out candidate
   outputs. Do not export private labels or claim invented text is original traffic.
   Failure reproductions must freeze before development selection/held-out calls.

No Critical or High contract finding identified. Both findings concern plan
acceptance coverage, not established implementation bugs. Proposed resolutions
were communicated to the coordinator; they are not yet verified here.
